## Exit gate assessment

| Gate | Implemented authority and evidence |
| --- | --- |

Student, attendance, homework, academics, activity, timetable and guardian-contact paths use it. Homeroom attendance and subject marks remain separate. `teacher-assignment-scope.int-spec.ts`, `teacher-scope-authorization.e2e-spec.ts` and service tests cover expiry, revocation, lock changes, substitutes, employment status and mismatched scope. Mobile `attendance_repository_test.dart` covers verified scope-version purge, late responses and revoked sync receipts. |
| Guardian policies | `StudentGuardian` carries tenant, student, guardian, relation, status, verification/approval, effective dates, capabilities and restriction evidence. `buildActiveGuardianRelationshipWhere` is shared by protected reads. `guardian-scope.int-spec.ts` covers unrelated, future/expired, suspended/revoked, unverified/unapproved, missing-capability and wrong-tenant denial, including custody suspension and identical phone numbers across schools. Mobile `parent_dashboard_offline_cache_test.dart` covers unlink, child switching, late responses and tenant/identity isolation. |
| Finance SoD | Canonical role templates separate cashier, clerk, accountant, approver, posting authority and auditor. Refund requests carry independent prepare/review/approval/execute evidence; journal drafts require independent review/approval/post; reconciliation sessions require independent review of exceptions and finalization. Fiscal reopen is a reason-bound approval request, not an immediate state change. `finance-domain-policy.int-spec.ts`, `journal-domain-policy.int-spec.ts`, `reconciliation-domain-policy.int-spec.ts` and `fiscal-reopen-domain-policy.int-spec.ts` exercise persisted lifecycle, self-approval denial, live grant/session checks, source drift, concurrency and audit rollback. |
| HR/payroll SoD | Payroll uses preparation, validation, review, approval, finalization and posting with separate actors and source fingerprints. Staff basic, document, identity, salary, bank and tax projections and mutations have separate permissions. `payroll-domain-policy.int-spec.ts` tests self-approval, sensitive-field projection, bank-data drift, finalized-history replacement, direct posting denial and audit rollback. Statutory payroll production readiness remains a later gate. |
| Security audit | Role/permission and scope changes, support access, sensitive staff/file reads, finance transitions, fiscal reopen and payroll finalization write scoped audit records. `AuditService` redacts protected payloads, supplies a UUID request ID when missing, supports system actors and propagates append failures. Domain transactions roll back on audit failure. There is no ordinary tenant route to update or delete audit rows. `audit.service.spec.ts`, `auth-administrative-concurrency.int-spec.ts`, the finance/payroll integration suites and Platform HTTP tests cover these boundaries. |
| Privilege escalation and Platform separation | Negative tests use actors with multiple duty grants, revoked grants, expired sessions, forged direct IDs and Platform/support identities. School-domain actions require live school identity plus scoped permissions; Platform authority is separate. Evidence is in the domain integration suites and `platform-hardening.e2e-spec.ts`. |

## Phase 2 edge-case review

The following groups record the roadmap triggers, expected authoritative behavior, user-visible result, risk, detection evidence, automated coverage and recovery. A denial is intentionally a stable forbidden/conflict response without leaking a different tenant, child or record. Recovery means correct the authoritative assignment/relationship/source or start a new reviewed workflow; a client must not silently retry with broader authority.

| Trigger / edge cases | Authority and user-visible behavior | Risk, detection, test and recovery |
| --- | --- | --- |
| Teacher has two subjects in one section; assignment starts/ends mid-day; bounded substitute; transfer while offline | Resolve the exact live assignment or time-limited delegation at action time. Show only current authorized scope; stale offline work receives explicit denial. | Prevent cross-subject/section writes and stale authority. Teacher scope integration/unit/HTTP tests plus mobile scope-version tests. Assignment audit and rejection code identify change; refresh current scope and retain a non-authoritative draft for resolution. |
| Homeroom teacher attempts other subject marks; subject teacher attempts homeroom attendance; former students linger in search/cache; marks or attendance lock changes after form load | Separate capabilities and re-check assignment, roster and lifecycle on submission/read. Deny stale locked writes and remove inaccessible cached scope. | Prevent role-name escalation and stale private reads. Teacher scope tests, attendance hardening and mobile late-response purge tests. Reload authorized roster/result; correction follows its controlled lifecycle. |
| Guardian has children at multiple schools; two guardians share contact; capability removed; custody restriction; relationship changes offline | Resolve guardian by authenticated tenant/user and active verified approved relationship, never by phone/email. A restricted/revoked link loses capability immediately server-side; child-scoped cache is pruned on verified refresh. | Prevent contact-based access and child leakage. Guardian Postgres tests and mobile cache tests; relationship audit/denial signal. Reverify the relationship and clear inaccessible cache; offline data is never authorization evidence. |
| Parent switches child with request in flight; removed child retains cached files/photos; direct ID for unrelated child | Child identity stays attached to the request and response; stale response cannot replace the new child's screen. Direct-ID and protected-file reads reauthorize. | Prevent cross-child display or IDOR. Guardian integration, mobile dashboard concurrency and private cache tests, file/media authorization tests. Discard stale response and purge removed-child storage. |
| Finance requester also has approver role; cashier has approver grant; refund exceeds source or source already reversed; threshold changes; approved source changes | Persist distinct human actors and bind requests to current source and policy evidence. Re-evaluate before approval/execution; deny self elevation, over-refund and stale source. | Prevent unauthorized money movement or stale approval. Finance Postgres suite covers multi-duty actors, source/policy drift, approval threshold, refund totals and replay. Return request for correction or create a fresh review; keep prior evidence. |
| Journal source changes, fiscal period closes mid-form, duplicate callback, concurrent reconciliation match | Re-check source and period in transaction; posting/callback identities and matching claims are idempotent or unique. Show a conflict/reload state, never a second official posting/match. | Prevent duplicate ledger impact and concurrent claim. Journal/reconciliation integration suites and existing callback replay tests. Reload source, resolve exception and re-review. |
| Reconciliation exceptions; fiscal reopen | Independent reviewer resolves exceptions before finalization. Reopen stays closed until reason-bound approval and separate executor; one pending request per target. | Prevent provisional balances becoming official or unreviewed period reopening. Reconciliation/fiscal integration and selected authenticated Web browser tests. Return, correct and re-review; retain old approvals and audit. |
| Payroll termination during cycle, bank or tax data changes, missing statutory input, temporary dual-duty actor | Readiness and source fingerprint are recalculated; independent review/approval cannot be supplied by preparer. Missing required data blocks authoritative finalization while remaining visible as a readiness issue. | Prevent wrong recipient/liability and self approval. Payroll readiness/service tests and Postgres SoD/source-drift suite. Correct staff/payroll evidence and revalidate, then obtain fresh independent approval. |
| Payroll rerun or reopen, retroactive salary edit, final record mutation, session expiry | Preserve finalized history, use linked correction and idempotent accounting handoff. Reject retroactive structure mutation and expired/revoked actor at the action boundary. | Prevent duplicate posting or rewritten payroll history. Payroll service/integration tests. Create a linked replacement/adjustment and re-run approvals; do not mutate issued history. |
| Audit append fails, actor is system, request ID missing, secrets in before/after, tenant admin attempts audit mutation | High-risk transaction rolls back if audit append fails. Store nullable system user and generated request ID; redact protected values. Tenant APIs only expose scoped reads. | Prevent unaudited actions and secret leakage. Audit unit and domain rollback tests, route review. Retry after audit storage recovers; investigate failed operation by request ID and reconcile before retry. |
